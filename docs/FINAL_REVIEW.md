## 本轮已修复的实质问题

1. 大整数和细微十进制变化被 Double 舍入漏报，及 related_pin 排序掩盖位置变化。
2. 未引号总线范围被冒号拆开、缺分号可能合并属性、未知转义的 token 长度少计、转义 NUL 接受。
3. 布尔 AND/XOR 优先级与 Liberty 规范不一致；数字开头引脚名的函数内引号引用不能解析。
4. 错配模板、标量附带索引、1D/3D 行形状、负转换时间和不支持的 SI delay_model 等边界。
5. 写出器在分配完整输出之后才检查预算；新增预检。公开标准检查先验证调用者 AST 的根、边界和预算。
6. 标准层只有少数扩展声明检查；本轮新增可追溯结构规则及 CLI 负例，独立样本从单一 PDK 扩大。

## 尚未完成的硬缺口与使用边界

- 全手册字段级目录尚未建立闭环；18 族规则不能称作全部分组/属性覆盖。所有标准作用域、参数、类型、引用及负例必须继续补齐。
- 全部合法词法边界、其他根结构（含所引用套件中的 phys_library）、向量/bank 规则、bus 默认端点/命名/展开、完整 CCS/ECSM/噪声/全部 LVF 格式语义仍开放。不能把“泛型 AST 能保存名字”当作这些已完成。
- 真正计算仍限标量/1D/2D NLDM；不执行三维、波形、统计、功耗、状态机仿真或路径 STA。完整格式目标不要求实现全套 EDA 计算器，但仍必须验证其数据格式。
- 严格分号语法拒绝当前 ASAP7 两个输入，不自动修补或冒充支持所有厂商方言。Nangate/IHP 的成功也不证明商业工艺库全面适用。
- 未重测全部规模/内存场景，不承诺无限大小库或商业签核正确性。Windows 原生依赖可出现既有 async C 层 EINVAL 宏重定义警告；MoonBit 严格检查通过，不将其误写成全部工具零警告。

因此，本轮工程问题已修复并有证据，完整标准承诺仍是终审前必须继续完成的工作。未对“无遗漏”或“官方必过”作未经证实的保证。
